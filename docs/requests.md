# 상대에게 요청

형식: `- [ ] 날짜 · 요청자 → 담당 · 내용`

- [ ] 2026-11-01 · 카로프 파루흐 → 전정현 · PDF 비밀번호 입력 화면 연결 (`server/pdf-password`, 서버 구현·가짜 LLM 테스트 완료)
  - `POST /documents` multipart에 선택 문자열 `password` 추가. 없으면 `401 {"detail":"PDF_PASSWORD_REQUIRED"}`, 틀리면 `401 {"detail":"PDF_PASSWORD_WRONG"}`. 정상 PDF와 성공 응답 형식은 그대로.
  - `extension/api.js`에서 `password`를 FormData에 넣고, `extension/viewer.js`에서 두 오류일 때 비밀번호 입력 → 같은 파일로 재시도. 취소 가능, 틀린 비밀번호는 재입력 안내, 문구는 `i18n.js`에 모으기.
  - 비밀번호는 요청 중 메모리에서만 사용. `chrome.storage`, URL, 로그, 오류 문구에 저장·표시하지 않기. 다운로드한 서명 URL은 서버로 보내지 않고 PDF 내용만 전송.
  - 서버는 메모리에서 잠금을 푼 PDF로 번역·OCR·페이지 그림·원본 보관을 처리. 복사·인쇄만 제한된 PDF는 입력창 없이 동작.
  - 함께 확인: 일반 PDF / 열기 비밀번호 없음 / 틀림 / 맞음 / 입력 취소 / 같은 PDF 다시 열기. 서버 전체 테스트 299개 통과, 실제 43쪽 교안 중 5·8·9쪽 OCR 오류 없음.
  - 일반 PDF는 Chrome 확장에서 직접 확인 완료: `1 블록체인 교과목 소개.pdf` 10쪽, 1·5·8·10쪽 이동, 번역/원문 나란히 보기, 텍스트 모드. 재요청 시 저장된 문서 GET 200 확인.
  - 번역 검수 참고: 영어 8쪽 `Attendance`·`Assignment`가 용어집의 소문자 `attendance`·`assignment`와 달라 경고 표시. 열기·페이지 표시는 정상이며 비밀번호 처리 오류와는 별개.
  - 추가 수정: 글이 같아도 그림·배치가 다른 PDF가 같은 캐시를 쓰던 문제 해결. 기존 ID·학습 기록은 유지되며 새 키 적용은 파일 재전송 시 이루어짐.
  - 합치기 전 `AGENTS.md` 3장 변경 확인 및 확장+서버 공동 점검 필요.
